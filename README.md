# CS 255 – System Analysis and Design
## DriverPass Project Portfolio

**Gabriel Santos**

### Project Overview

The DriverPass project focused on designing a system for a company that helps students prepare for their driving tests. The client, DriverPass, wanted a web-based system that would allow customers to purchase training packages, schedule driving lessons, take online practice tests, and track their progress. The system also needed to help employees manage appointments, instructors, vehicles, and customer information.

### What Did I Do Particularly Well?

I believe one of my strengths in this project was organizing the client's requirements and translating them into a structured system design. I focused on understanding what customers and employees needed and how the system could support their daily activities. I also did well connecting the business requirements to the system diagrams, especially when identifying different user roles and explaining how the scheduling process should work.

### What Would I Improve?

If I could revise one part of my work, I would improve the activity diagrams by including more details about alternative scenarios and possible errors. For example, I would explain what should happen when a customer tries to schedule a driving lesson but no instructor or vehicle is available. Adding these details would make the design more complete and help developers understand how the system should respond to different situations.

### Understanding User Needs

I interpreted the user's needs by reviewing the DriverPass interview and identifying the main features the client expected from the system. I used this information to develop functional and nonfunctional requirements and create a system design that supported customers, instructors, and administrators. I learned that understanding user needs is one of the most important parts of software development because a system can work technically but still fail if it does not meet the expectations of the people using it.

### My Approach to Software Design

My approach to software design starts with understanding the problem and gathering clear requirements before developing a solution. I believe communication, documentation, and planning are essential to creating an effective system. In future projects, I would continue using techniques such as requirements analysis, use case diagrams, and activity diagrams to organize information and identify potential problems early. I would also focus on security, usability, testing, and maintenance to make sure the system is reliable and easy to use.
